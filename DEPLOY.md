# Deploy Corridor (free): GitHub → Render → Vercel

| Piece | Host | Notes |
|--------|------|--------|
| Backend API | **Render** (free web service) | Django + Gunicorn |
| Frontend SPA | **Vercel** (Hobby) | Vite React build |

**This repo:** https://github.com/syedusman00/corridor  
**Deploy branch:** `render-vercel-deploy-prep`  
**Status report:** [DEPLOYMENT_REPORT.md](./DEPLOYMENT_REPORT.md)

**Do not claim the app is live until both public URLs respond** (steps 6–7).

Secrets (`HERE_API_KEY`, `DJANGO_SECRET_KEY`, production `.env`) must **never** be committed to GitHub.

---

## 0. Prerequisites

- GitHub account
- [Render](https://render.com/) account
- [Vercel](https://vercel.com/) account
- Optional: valid [HERE API key](https://platform.here.com/) (otherwise OSRM driving fallback)

Locally confirm:

```bash
cd backend && python manage.py test routing
cd ../frontend && npm run build
```

---

## 1. Prepare the GitHub repository

### 1.1 Confirm secrets are ignored

`.gitignore` already excludes:

- `backend/.env`
- `frontend/.env`
- `frontend/.env.local`
- `node_modules/`, `venv/`, `dist/`, `staticfiles/`

**Never** add `.env` or paste API keys into source files.

### 1.2 Create the repo and push

From the project root (`Corridor` / `New folder (2)`):

```bash
git init
git add .
git status
# Double-check: backend/.env must NOT appear in staged files
git commit -m "Prepare Corridor for Render and Vercel deployment"
```

On GitHub: create a **new private or public repository** (empty, no README).

```bash
git branch -M main
git remote add origin https://github.com/<YOUR_USER>/<YOUR_REPO>.git
git push -u origin main
```

## 2. Deploy the backend on Render

### Option A — Blueprint (`render.yaml`)

1. Render Dashboard → **New** → **Blueprint**
2. Connect the GitHub repo
3. Render detects `render.yaml` → service `corridor-api`
4. Before apply, open **Environment** and set:

| Key | Value |
|-----|--------|
| `CORS_ALLOWED_ORIGINS` | Leave blank for now; update after Vercel URL exists (or use a placeholder) |
| `CSRF_TRUSTED_ORIGINS` | Same as CORS (optional for this API) |
| `HERE_API_KEY` | Your HERE key, or leave empty for OSRM |

`DJANGO_SECRET_KEY` is auto-generated by the blueprint.

5. Create / apply the blueprint and wait for the first deploy.

### Option B — Manual Web Service

1. **New** → **Web Service** → select the repo  
2. Settings:

| Field | Value |
|--------|--------|
| Root Directory | `backend` |
| Runtime | Python 3 |
| Build Command | `pip install -r requirements.txt && python manage.py collectstatic --no-input && python manage.py migrate --no-input` |
| Start Command | `gunicorn config.wsgi:application -c gunicorn.conf.py` |
| Instance | **Free** |
| Health Check Path | `/api/health/` |

3. Environment variables:

| Key | Value |
|-----|--------|
| `DEBUG` | `False` |
| `DJANGO_SECRET_KEY` | Generate a long random string |
| `ALLOWED_HOSTS` | `.onrender.com` |
| `SECURE_SSL_REDIRECT` | `True` |
| `ROUTING_PROVIDER` | `here` |
| `GUNICORN_TIMEOUT` | `120` |
| `HERE_API_KEY` | optional |
| `CORS_ALLOWED_ORIGINS` | set after Vercel (step 4) |

4. Deploy and copy the public URL, e.g.:

`https://corridor-api-xxxx.onrender.com`

### 2.1 Backend smoke check (required)

In a browser or terminal:

```bash
curl https://<YOUR-RENDER-SERVICE>.onrender.com/api/health/
```

Expect JSON like:

```json
{"status":"ok","here_configured":false,"routing_provider":"here",...}
```

If this fails, **do not** continue to Vercel until it works.

> Free Render services **spin down** after idle time. The first request after sleep can take 30–60s.

## 3. Deploy the frontend on Vercel

1. [vercel.com](https://vercel.com) → **Add New Project** → import the GitHub repo  
2. Configure:

| Field | Value |
|--------|--------|
| Framework Preset | Vite |
| Root Directory | **`frontend`** (Important) |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | `npm install` |

3. **Environment Variables** (Production + Preview):

| Name | Value |
|------|--------|
| `VITE_API_URL` | `https://<YOUR-RENDER-SERVICE>.onrender.com` |

**No trailing slash.** Example: `https://corridor-api.onrender.com`

4. Deploy. Copy the frontend URL, e.g.:

`https://corridor-xxxxx.vercel.app`

---

## 4. Wire CORS (Render ← Vercel)

Back in **Render** → `corridor-api` → **Environment**:

| Key | Value |
|-----|--------|
| `CORS_ALLOWED_ORIGINS` | `https://corridor-xxxxx.vercel.app` |
| `CSRF_TRUSTED_ORIGINS` | `https://corridor-xxxxx.vercel.app` |

(Use your real Vercel URL. No trailing slash.)

The API also allows `*.vercel.app` via regex for preview deployments.

**Manual Deploy** / restart the Render service so env vars apply.

---

## 5. Redeploy Vercel (if you changed env after first build)

`VITE_API_URL` is baked in at **build time**. If you set it after the first deploy:

Vercel → Deployments → **Redeploy** (with “Use existing Build Cache” **off**).

## 6. Verify both public URLs (required)

### Backend

```bash
curl https://<RENDER>.onrender.com/api/health/
```

### Frontend

1. Open `https://<VERCEL>.vercel.app`
2. Confirm the status pill shows API online (may take a minute if Render was asleep)
3. Run **Chicago, IL → Denver, CO** (interval 50 mi for speed)
4. Confirm:
   - Up to 3 routes / recommendation
   - Map tiles + route lines + checkpoints
   - Weather table + risk labels
   - 0–48h heatmap slider

### API analyze (optional)

```bash
curl -X POST https://<RENDER>.onrender.com/api/analyze/ \
  -H "Content-Type: application/json" \
  -d "{\"origin\":\"Chicago, IL\",\"destination\":\"Denver, CO\",\"departure\":\"2026-10-24T18:00:00+00:00\",\"load_lbs\":35000,\"interval_miles\":50}"
```

Expect HTTP 200 and `routes` in the JSON (can take 15–60s on free tier).

## 7. Success criteria checklist

Only mark deployment successful when **all** are true:

- [ ] `https://<RENDER>/api/health/` returns `status: ok`
- [ ] `https://<VERCEL>/` loads the Corridor UI
- [ ] Browser Network tab: analyze calls go to the Render host (not localhost)
- [ ] Routes, map, checkpoints, recommendation, and heatmap work on the live site
- [ ] No `.env` or API keys in the GitHub repo

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| CORS error in browser | Set `CORS_ALLOWED_ORIGINS` to exact Vercel URL; redeploy Render |
| Frontend calls localhost | `VITE_API_URL` missing/wrong → set + **redeploy** Vercel |
| 502 / timeout on analyze | Raise `GUNICORN_TIMEOUT`; wait for Render cold start |
| Blank map on Vercel | Hard refresh; confirm OpenFreeMap/tiles not blocked |
| HERE still OSRM | Invalid/missing `HERE_API_KEY` on Render (expected without a valid key) |
| `DisallowedHost` | Ensure `ALLOWED_HOSTS=.onrender.com` and service hostname matches |
